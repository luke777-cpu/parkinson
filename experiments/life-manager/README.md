# Parkinson Life Manager v1.2 · 기존 약효일지 통합 실험판

GitHub `luke777-cpu/parkinson`의 기존 약효일지(root 앱)를 스케줄러 안에 연결한 Windows 실험판입니다. P1 앱은 대상이 아닙니다. 운영 GitHub Pages와 기존 PC 데이터는 바꾸지 않습니다.

## 실행

이전 앱을 종료하고 ZIP 전체를 새 폴더에 풀어 `ParkinsonLifeManager.exe`를 실행하세요. 먼저 `Demo.cmd`로 가상 일정과 Output 기록을 볼 수 있습니다. 별도 Python 설치가 필요 없으며 Chrome/Edge와 .NET Framework 4.x가 필요합니다.

좌측 메뉴 → **기존 약효일지 · 실험** → 일지 화면 상단의 **Output 양방향 교환**을 누르세요. 일지에 입력한 숫자 Output은 스케줄러의 실제 기록 시간표·약효 화면으로, 스케줄러에서 입력한 Output은 일지로 보냅니다. 자동 실시간 동기화는 아닙니다. 다른 화면으로 전환할 때도 교환 버튼을 눌러야 반영됩니다.

처음에는 Demo.cmd로 시험하세요. 정상 실험 데이터는 `%LOCALAPPDATA%\ParkinsonLifeManager-DiaryExperiment\life.db`, 시연 데이터는 프로그램 폴더의 `demo-data`입니다. v1.1 정상 데이터와 분리되어 있습니다. 이 패키지는 설치 프로그램을 제공하지 않는 압축 해제 실행판입니다.

## 구현한 범위

- v1.1의 월간·주간·오늘·반복 일정·할 일·하루 틀을 유지합니다.
- 기존 약효일지 화면과 기능을 로컬 iframe으로 제공합니다. 운영 사이트 계정·브라우저 저장소를 자동으로 읽지 않습니다.
- 약효일지를 수정하면 전체 원본 문서를 SQLite journal에 새 UUID·부모 revision·생성시각으로 저장합니다. 알 수 없는 필드도 보존하며 이전 문서를 덮어쓰지 않습니다. 같은 내용의 저장은 새 revision을 만들지 않습니다.
- 원본 일지의 `events[type=state].output`에서 실제 숫자 0~100 정수와 기록 시각이 있는 항목만 교환합니다. null을 0으로 바꾸지 않습니다. 원본 ID를 대응표로 관리하여 재교환 중복을 막습니다.
- 스케줄러에서 생성한 Output은 일지에서 ‘Output만 기록 · ON/OFF 미기록’으로 표시합니다. ON/OFF나 추세를 점수로 추정하지 않습니다. 시각은 같은 순간을 유지하며 일지→스케줄러 표시는 +09:00입니다. 원본에 시간대 정보가 없다면 원래 시간대를 복원할 수 없습니다.
- 수정은 각자의 이력을 남깁니다. 양쪽이 같은 기록을 동시에 수정하면 전체 교환을 취소하고 충돌을 알립니다. 자동으로 최신 기록을 고르지 않습니다. 충돌 해결 편집 UI는 아직 없으며 양쪽 JSON을 내보내 비교해야 합니다.
- 원본 일지의 **예정시간 경과에 따른 복용 자동 추정**은 이 실험판에서 껐습니다. 원본에 이미 들어 있던 assumed 기록은 삭제하거나 확정 기록으로 변환하지 않습니다.

## 교환하지 않는 항목

복약·세트·증상·ON/OFF·예측·삭제는 현재 양방향 교환하지 않습니다. 이 정보는 약효일지 원본 journal에만 그대로 보존합니다. 일지의 ON/OFF 일부는 파생 값이므로 스케줄러의 명시적 ON/OFF로 옮기지 않습니다. 삭제를 다른 쪽으로 전파하거나 삭제된 기록을 되살리지 않습니다. 통합 앱의 복약 화면과 기존 일지의 복약 화면은 아직 각각 별도 기록입니다.

기존 일지를 가져오려면 운영 일지에서 먼저 JSON 백업을 만든 뒤 실험 일지의 불러오기를 사용하세요. 이 작업은 실험 일지의 현재 화면 문서를 대체하지만 이전 snapshot은 journal에 남습니다. 원본 운영 일지는 변경되지 않습니다. 처음에는 개인정보를 지운 복사본으로 시험하세요.

## 저장·백업 주의점

상단에 **SQLite 저장됨**이 표시된 뒤 화면을 이동하거나 종료하세요. 저장 대기·실패 중에는 메뉴 이동을 막습니다. 실패하면 **원본·변경 이력 내보내기**로 미저장 원본까지 보존한 뒤 다시 여세요.

일지의 기존 백업 버튼은 현재 일지 문서를 내보냅니다. 통합 바의 변경 이력 내보내기는 모든 journal 문서를 보관합니다. 스케줄러의 기존 PLM JSON에는 일지 원본·대응표가 포함되지 않습니다. 기존 ‘안전 복원’도 일지 journal 복원을 지원하지 않습니다. 전체 실험 상태를 옮기려면 앱을 종료하고 실험 데이터 폴더 전체를 복사하세요. journal 내보내기 파일의 자동 복원 UI는 미구현입니다.

Windows 앱 창은 기본적으로 포트가 바뀌어도 SQLite에서 일지 원본을 다시 읽습니다. 원본 일지가 쓰는 localStorage는 화면 호환용 캐시이며 주 저장소가 아닙니다. 서비스 워커는 통합판에서 등록하지 않습니다. OCR 등 원본의 선택적 온라인 기능은 이번 검증 범위에 포함하지 않습니다.

## 검증

`RunTests.cmd` 또는 소스 폴더에서 `runtime\python.exe -m unittest discover -v`로 테스트합니다. 브리지 10개와 기존 66개를 포함합니다. 가상 데이터로 화면 열기, 실제 일지 저장 함수, 양방향 교환, 재교환 중복 방지, 자동 복용 추정 비활성화, 포트가 바뀐 재실행의 복원을 검증했습니다. 실제 개인 기록 및 다른 실물 PC의 검증은 하지 않았습니다.

출처와 수정 범위는 SOURCE.md를 참조하세요. 이것은 통합 가능성을 확인하는 첫 실험판이며 완전한 복약·증상 동기화 버전이 아닙니다.
