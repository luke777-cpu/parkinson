# P1 나의 약효 실험실 — 구현 설계도 v1.0

## 1. 목적과 첫 검증 질문

‘왜 오늘은 평소와 달랐는가?’를 살펴볼 개인 관찰 도구다. 첫 번째 검증 질문은 **평소 패턴에 최근 출력을 보정하면, 단순 평소 패턴 또는 현재 출력 유지보다 이후 출력 오차가 작아지는가?**다. 기록을 저장한 횟수를 효과로 간주하지 않는다.

원인 탐색은 반복 관찰에서 후보를 찾는 단계로 한정한다. 기록 누락, 식사·수면·복약 시각의 동시 변화, 증상이 나빠져 구제약을 복용하는 역인과 때문에 관찰 자료만으로 인과관계를 확정하지 않는다.

## 2. 기본 시간표

| 시각 | 기본 약물 |
|---|---|
| 06:00 | 퍼킨 CR 100mg, 미라팩스 서방정 0.375mg, 아만타딘 100mg |
| 07:20 | 퍼킨 즉방정 100mg |
| 12:00 | 퍼킨 CR 100mg, 아질렉트 1mg |
| 18:00 | 퍼킨 CR 100mg, 아만타딘 100mg |
| 18:15 | 마도파 확산정 100mg |

표준은 편집할 수 있다. 실제 복용은 별도 확인으로 기록하며, 과거 사실을 표준 변경에 맞추어 바꾸지 않는다. 범위가 아닌 기본 시각으로서 18:00/18:15를 사용한다.

## 3. 몸의 기준 패턴

기상 출력 20~30, 07:50 약 60, 08:20~08:30 약 90, 오전 ON 유지. 10~12시 중 이상운동증 30~60분 후 정오 50~60. 오후 14~15시 60~70, 간혹 70~80으로 짧게 상승. 16시 이후 급하강, 17~18시 OFF. 확산정 후 60~90분에 약 80, 저녁 ON 유지 불안정. 22~23시 이상운동증 뒤 30~40.

기준선은 범위의 중간값과 대표 시각을 연결한 **도식**이다. 저녁 불안정의 진폭이나 OFF 점수는 새로 만들어 넣지 않았다. 16:30~19:00 기준점은 null로 두어 미확인 구간을 비운다. 실제 곡선이나 학습 정답으로 취급하지 않는다.

## 4. 화면 흐름

1. 날짜 선택과 하루 겹친 그래프.
2. 현재 출력 큰 숫자·±10·슬라이더·선택 메모.
3. 복약 확인 및 필요할 때만 사건 기록.
4. 하루 기록을 표준 대비 비교.
5. 저장된 예측과 실제 결과의 오차 확인.
6. 표준값 편집과 JSON 백업·복원.

그래프는 06~24시를 표시한다. 06시 이전 실제 기록도 저장·목록·분석에는 포함하지만 그래프에는 그리지 않는다. 실제 점 사이 2시간을 넘는 공백은 연결하지 않는다.

## 5. 구성과 저장

외부 의존성 없는 단일 HTML에 엔진과 화면 코드를 내장한다. 선택적으로 Python 표준 라이브러리 서버가 localhost:8879에서 그 HTML만 제공한다. 설치 패키지나 API 키는 필요 없다.

localStorage `p1-lab-v1`에 다음을 저장한다.

- schedule: 기준 복약표의 항목 ID, 약물·제형, 용량, 시각.
- baseline: 시각과 출력 기준점. 미확인은 null.
- events: 고유 ID, 기록일, 실제 시각(분), 종류, 값, 메모, 생성·수정 시각. 종류는 output / med / factor.
- forecasts: 생성 시각, 목표 시각, 예측값, 당시 기준값, 당시 최근 출력, 방법·입력기록 ID.

다른 탭에서 자료가 바뀌면 덮어쓰기를 차단한다. 잘못된 저장 자료를 만나면 빈 자료로 덮지 않는다. JSON 복원은 형식을 검증하고 전체 교체 전 사용자 확인과 현재 자료 다운로드를 수행한다. CSV는 내보내기만 지원한다. 기록 저장 오류는 사용자에게 알린다.

## 6. 약물 모형

기존 parkinson `simulation-drugmodel.js`의 계산을 그대로 사용한다. 퍼킨 CR을 HBS/CR 공통 모형에 명시적으로 연결하고, 마도파 확산정은 즉방 모형을 따른다.

약물 출력값은 포화 변환된 0~100 지수이며 실제 혈중농도, 실제 출력, LEDD 시간곡선으로 부르지 않는다. 미라팩스·아만타딘은 반복 복용 누적 가정, 아질렉트는 평탄 배경효과를 유지한다. ‘실제 확인된 복약만’ 모드도 그 가정을 유지하므로 완전한 실제 약동학 계산이 아니다. 전날 레보도파는 포함하지 않는다. 원 엔진의 경험적 상수는 이 앱에서 임상 검증하지 않았다.

## 7. 출력 예측 v1

미래 예측값 = 평소 기준선의 미래 값 + 최근 출력의 기준 대비 차이 × 감쇠.

- 오늘 현재 시각에 생성한다. 과거 날짜에는 새 예측을 만들지 않는다.
- 최근 120분 내, 현재보다 늦지 않은 출력만 사용한다.
- 차이는 ±25로 제한하고, 최근 출력 시각에서 목표 시각까지 90분 시정수의 지수 감쇠를 적용한다.
- 30·60·120분 목표를 계산한다. 기준선이 비어 있거나 자정을 넘으면 보류한다.
- 최근 출력이 없으면 평소 패턴만 사용한다.
- 출력 범위 0~100으로 제한한다. 확률·신뢰구간은 아직 추정하지 않는다.
- 생성 당시 예측과 비교 기준을 고정 저장한다. 나중에 표준값·기록이 바뀌어도 예측값을 다시 계산하지 않는다.

약물 변경·요인은 v1 출력 예측의 입력으로 아직 사용하지 않는다. ‘약물 모형과 출력 간 개인 전달함수를 학습했다’고 주장하지 않는다.

## 8. 검증

목표 시각 ±15분 안의 실제 출력 중 가장 가까운 사후 기록을 연결한다. 생성 시각보다 먼저 입력된 과거 자료는 평가 대상으로 쓰지 않는다. 예측값, 당시 평소 패턴값, 당시 최근 출력을 유지한 값의 절대오차를 비교한다. 현재 버전은 전체 평균 절대오차와 최근 50건 상세표를 표시한다.

같은 출력이 여러 목표에 연결될 수 있으므로 예측 건수를 독립 표본수로 보지 않는다. 선택적 기록 편향·사후 수정·적은 표본은 남은 한계다. 날짜별 완전한 분리, 전망 시점별 평가, 불확실성 보정은 다음 단계다.

## 9. 이유 탐색

평소와 비교 가능한 출력이 하루 3점 이상 있는 날에 대해, 기록 시점별 (실제−표준) 차이의 일 평균을 낸다. 요인 기록이 있는 날/미기록일을 나누고 각 3일 이상일 때 평균 차이를 제시한다. 출력 빈도 자체가 다른 날을 동일 일자 단위로 비교하되, 기록 시각·복약·다른 변수의 교란은 통제하지 못한다.

요인 부재가 아니라 **미기록**으로 표기한다. 이는 인과효과 추정이 아니며, 약을 바꾸라는 권고는 생성하지 않는다.

## 10. 검증 완료 범위와 다음 단계

코어 및 DOM 모의 환경에서 초기 빈 기록, 미래정보 차단, 미확인 보류, 최근 출력 보정, 예측 불변성, 결과 매칭, 데이터 검증, 실제 기록 수정·삭제·취소, 그래프 전환, 요인 기록, 저장 복구, 탭 충돌을 시험했다. 실제 Windows·iPhone 브라우저에서의 사용자 실행과 기기별 저장 정책은 별도 확인이 필요하다.

다음 버전 후보: 기존 앱 JSON의 읽기 전용 변환, 시간대별 개인 예측 학습, 날짜 단위 전향 검증, 식사·수면 등 구조화된 변수, 출력 및 실제 보행 지표 결합. 이후 충분한 자료와 설계를 갖춰 인과 질문을 다룬다. 현 단계에서 처방 조정 자동화는 하지 않는다.
